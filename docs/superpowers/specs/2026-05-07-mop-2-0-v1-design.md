# MOP 2.0 v1 Design

## Purpose

This spec defines the first corrective build for the post-purchase `MOP` loop after the recent `Active MOP / Next Home`, landlord ops, and life-income releases.

Research and live playtesting show that the game has fixed the old `nothing to do during MOP` problem at the framing level, but not yet at the month-resolution level. Players now understand that MOP is a preparation phase for the next home, but several monthly choices still collapse into the same abstract life-income outcome.

This build should make the first ownership chapter feel more distinct, more stateful, and less repetitive without opening a huge new subsystem surface.

## Product Thesis

`MOP` should feel like a playable campaign chapter, not a renamed waiting room.

The player should feel three things during the first ownership stretch:

```txt
I know what this month is for.
This month did something specific.
The next milestone is visible.
```

## Problem Statement

Current `main` has four linked issues:

1. Multiple MOP monthly intents still resolve through the same `property-hustle` life action.
2. `Use plan + advance` often does not do the specific thing the card promises.
3. The first-owner rail ends too early, so MOP loses chapter pull after the first tenant or reserve click.
4. `Blitz 3` compresses low-signal time, but does not distinguish between quiet months and genuinely notable months.

## Goals

1. Make MOP monthly intents feel distinct in both behavior and recap.
2. Let the one-click MOP path perform small safe ownership actions where appropriate.
3. Extend the guided ownership rail into a short MOP campaign instead of ending at first activation.
4. Replace generic multi-month skipping with a more contextual `next notable month` fast path.
5. Keep the implementation compatible with later family, event-density, and market-intel expansions.

## Non-Goals

1. Do not build the full long-term `MOP 2.0` vision in this slice.
2. Do not add new major tabs.
3. Do not build full family simulation, community systems, or differentiated business careers here.
4. Do not introduce a deep watchlist or charting system yet.
5. Do not replace the current landlord / renovation systems; use and route them better.

## Scope Decision

Ship `MOP 2.0 v1` as one coherent slice with four parts:

1. `Intent-aware month resolution`
2. `Safe one-click ownership actions`
3. `First MOP campaign rail`
4. `Advance to next notable month`

This is intentionally narrower than the full research roadmap. The point is to change the feel of the first ownership chapter now while keeping the repo stable.

## Design

### 1. Intent-Aware Month Resolution

Monthly intent should become first-class state, not just a temporary pair of life actions.

When the player chooses a monthly intent, the game should retain:

```txt
intent id
intent label
intent focus track
```

That context should be stored in the selected life state, copied into the resolved month summary, and used by the recap instead of reconstructing the month only from life-action IDs.

This means:

- `Grow Next-Home Cash` should recap like a cash-runway month
- `Improve Current Home` should recap like a property-improvement month
- `Study Exit Market` should recap like a planning / market-intel month
- `Activate Room Rental` should recap like an ownership-ops month

The recap does not need a fully separate engine for each path yet, but it must stop flattening all MOP months back into the same language.

### 2. Safe One-Click Ownership Actions

The one-click MOP path should perform small real ownership actions before the turn advances.

`Use plan + advance` should keep the current life-action setup, but where the chosen MOP intent clearly maps to a safe ownership move, the game should auto-apply that move first.

Supported v1 actions:

- `landlord-ops`
  - if the first MOP-active HDB has no tenant, auto-start a compliant `room-rental` tenant strategy
- `mop-home-project`
  - if the current home has no active renovation and can afford a small stable project, auto-start `flooring-paint`
  - otherwise, if reserve cash is still below `S$5K` and the player can afford it, auto-protect `S$5K` reserve
- `mop-income-runway`
  - no ownership auto-action; stay a life-income month
- `mop-market-intel`
  - no ownership auto-action yet; keep it a planning month, but recap it distinctly

These actions should remain conservative. The player must still use `Open first` for explicit manual planning.

### 3. First MOP Campaign Rail

The current first-run quest should transition into a short MOP campaign once the player owns a first home and is inside active MOP.

The replacement rail should feel like a real chapter, not a finished tutorial.

Initial v1 steps:

1. `Activate income from the home`
   - complete when room rental is live or a tenant is active
2. `Protect reserve`
   - complete when reserve cash reaches `S$5K`
3. `Improve the current home`
   - complete when the player starts or completes a renovation, or reaches strong condition
4. `Build next-home runway`
   - complete when readiness reaches a meaningful threshold

This campaign does not need to cover all 60 months. It only needs to bridge the handoff from “I just bought” to “I’m actively preparing the next move.”

### 4. Advance To Next Notable Month

Replace the `Blitz 3` framing in the Next Home gateway with a more contextual skip:

```txt
Advance to Next Notable Month
```

The behavior should advance month-by-month until one of these occurs:

- a scenario appears
- the MOP months-left counter crosses a milestone checkpoint
- the recommended focus changes
- the bottleneck changes
- active renovation count changes
- maintenance issue count changes
- tenant/lease state changes

The method should still cap the skip length to avoid surprising long jumps.

This keeps quiet months fast while preserving meaning when the run becomes interesting.

## UX Changes

### Dashboard / Next Home Gateway

Update the gateway card to:

- emphasize `Next Home Plan`
- show `ready before / after MOP` pacing more clearly
- replace `Blitz 3` with `Next notable month`

### Last Month Recap

The recap should use intent context for:

- title
- summary framing
- next hint
- one fact or note that reflects what the chosen month was trying to achieve

### Quest Panel

The panel can keep the current component shell, but its content should switch from `First 3 Moves Quest` to a `First MOP Campaign` variant when appropriate.

## Data Model

Add lightweight intent context to life state and month summary:

```txt
selectedMonthlyIntentId
selectedMonthlyIntentLabel
selectedMonthlyIntentTrack
```

Do not add a giant new campaign state tree in this version.

Any notable-month skip logic should derive from current game state, not from a separate scheduler model.

## Testing

Add or extend tests for:

1. monthly intents preserving intent context in resolved month summaries
2. MOP auto-actions firing safely
3. MOP campaign rail continuing after first ownership activation
4. notable-month skipping stopping on signal changes
5. recap titles and hints reflecting selected MOP intent rather than only life actions

## Success Criteria

This slice is successful if:

1. a live MOP month no longer feels identical to a generic `property-hustle` month
2. the first post-purchase chapter still has a visible guided milestone after the first tenant / reserve step
3. the player has a fast-forward path that skips quiet months but still stops when something interesting changes
4. browser playtesting shows a clearer sense of “this month did something specific”

## Follow-On Work

If `MOP 2.0 v1` lands well, the next higher-order expansions should be:

1. differentiated MOP event density
2. family / space-pressure milestones
3. market-intel progression state
4. richer business / career identity paths

Those should build on this slice, not replace it.
