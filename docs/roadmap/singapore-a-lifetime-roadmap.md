# Singapore: A Lifetime Roadmap

## Product Thesis

Singapore Property Simulator should evolve into **Singapore: A Lifetime** without discarding the current simulation work.

The property, CPF, loan, duty, MOP, tenant, renovation, reserve, and buyer-profile systems remain the simulation backbone. The new player-facing wrapper turns those systems into a life story with named endings, memories, cultural texture, and replay identity.

The intended experience is:

> A realistic Singapore life tycoon where property is the biggest financial and emotional anchor, but not the only thing the player cares about.

## Why This Re-Steer Exists

The current game is mechanically rich, but several playtests point to the same gap:

| Missing Layer | Why It Hurts |
|---|---|
| Named endings | Runs currently end as a number target or bankruptcy, so players have little to collect across runs. |
| Emotional arc | The game teaches property decisions, but does not yet make players remember the specific life they lived. |
| Causal randomness | Events can feel like noise unless they clearly respond to past choices and ownership behavior. |
| Thin life actions | Energy and stress exist, but they need more memorable consequences and identity tags. |
| Everyday Singapore texture | The rules are Singaporean, but the lived flavor needs more kiasu parents, kopi talk, NS, wedding costs, school pressure, neighbour drama, and estate life. |
| Net-worth-only win | The ending should answer "what kind of Singaporean did you become?" before it shows the final score. |

## Design Principles

1. **Realism underneath, fun on top.**
   The engine should stay credible, but players should primarily see choices, stakes, memories, and consequences.

2. **Education at the moment of consequence.**
   Explain ABSD when the second-home tax hurts. Explain MOP when the player wants to sell or rent. Explain TDSR when the bank rejects the dream home.

3. **One clear move.**
   Every major screen should answer "what should I do now?" and keep deeper simulation details available as optional inspection.

4. **Causality beats random noise.**
   Scenario probability should be affected by property state, tenant satisfaction, life stress, family pressure, leverage, district identity, and prior choices.

5. **Replay through identity.**
   Runs should be remembered by endings, life memories, and household starts, not only by net worth.

6. **No full rewrite.**
   The current simulator remains valuable. The roadmap adds a lifetime layer around it instead of replacing it.

## Target Player Experience

### First Run

The first run should feel guided and readable:

1. Pick a beginner-friendly household start.
2. Choose a life goal such as "Stable Family Home", "Upgrade Ladder", "FIRE", or "Heartland Landlord".
3. Follow one clear recommended move each month or milestone.
4. Learn terms only when they block or change a decision.
5. Finish with a named ending and a life-summary card.

### Repeat Runs

Repeat runs should invite experimentation:

1. Try a different household start.
2. Chase an undiscovered ending.
3. See different causal events because prior choices differ.
4. Compare life summaries and ending collection.
5. Eventually continue through a child or legacy handoff.

## What Current Work Becomes

| Current System | New Role In Singapore: A Lifetime |
|---|---|
| Property engine | Simulation truth for homes, loans, taxes, MOP, rent, maintenance, and resale. |
| Run Director routes | Life goals and route flavor. |
| Decision Coach | Life Coach with one clear move, one risk, and one opportunity. |
| MOP 2.x systems | Home Season campaign for the first 60 ownership months. |
| Life actions | Monthly life posture that can generate memories, identity tags, and causal event weights. |
| Achievements | Secondary badges behind named endings. |
| Game Over screen | Life Summary screen with ending, memories, score, lessons, and replay prompt. |
| Save profiles | Local household profiles and future run-history storage. |
| Learn hub | Just-in-time explanation library for terms encountered during play. |

## Development Roadmap

### Phase 1: Lifetime Shell v1

**Status:** Shipped in the current `main` line. The game now has named ending definitions/detection, life memories from existing gameplay events, local ending collection/run history, a life-summary Game Over screen, and Dashboard copy that frames each route as a Singapore life goal.

**Purpose:** Make the existing game feel like a life story before adding large new domains.

**Build:**

- Named ending definitions and detection.
- Life-memory log generated by existing events.
- Life-summary game-over screen.
- Local run-history and ending collection.
- Dashboard copy that frames the current route as a life goal.
- README and changelog updates that introduce the new direction without overstating shipped features.

**Success criteria:**

- A completed run earns a named ending.
- The game-over screen explains why that ending was earned.
- At least 5 endings are achievable using existing systems.
- At least 6 memory types can be created without adding full family or dynasty systems.

### Phase 1.5: Life Board And Living Homes

**Status:** Shipped in the current `main` line. The game now has a visual life-board surface, living-home dioramas, calmer navigation/CTA treatment, restored guided-mode entry points, mobile-safe advance-month placement, and route-specific visual postcards.

**Purpose:** Make the existing simulation feel less like an Excel/dashboard surface and more like a serious Singapore life game, without hiding the real CPF, loan, duty, MOP, rental, and maintenance mechanics underneath.

**Build:**

- Life Board framing for Foundation, First Home, Home Season, Upgrade Window, and Ending.
- Living-home diorama states for owned property, tenant status, condition, reserve pressure, and monthly income.
- Visual page postcards for Dashboard, Buy, Own, Bank, Market, Life, Learn, and New Game surfaces.
- Mobile UX cleanup so the advance-month action stays reachable without covering key stats.
- Guided-mode recovery so players can turn help back on after disabling it.

**Success criteria:**

- The first visible screen communicates "this is a life/property game" before detailed numbers appear.
- Players can advance time from the main flow without hunting for the control.
- Route switches land at the top of the destination screen.
- The UI keeps serious finance credibility while feeling more visual and playable.

### Phase 2: Causal Story Events v1

**Purpose:** Make randomness feel earned.

**Build:**

- Scenario weighting inputs from landlord behavior, stress, leverage, reserves, ownership status, district type, and route.
- Visible "why this event happened" copy.
- Event cooldowns to prevent repeated similar beats.
- Scenario outcomes that create stronger life memories and ending signals.
- A first content pack focused on high-impact, Singapore-specific everyday beats: tenant trust, neighbour friction, family pressure, kopi talk, school-zone anxiety, renovation delays, and market chatter.
- Tests proving good landlord behavior reduces tenant-crisis likelihood and high leverage increases finance-stress likelihood.

**Success criteria:**

- Scenario logs can explain the strongest trigger.
- At least 8 scenario families respond to player state.
- Players can infer how their choices affected event risk.
- Two runs with different life/property behavior should produce noticeably different story texture before reaching the same net-worth range.

### Phase 3: Life Actions 2.0

**Purpose:** Turn life actions into story and identity, not only stat deltas.

**Build:**

- Action streaks and identity tags such as `grinder`, `family-first`, `kiasu`, `risk-taker`, `burned-out`, and `community-rooted`.
- Action-specific memory generation.
- Stronger tradeoffs between money, stress, family load, career momentum, and future event risk.
- A clearer monthly recap that says what kind of life pattern is forming.

**Success criteria:**

- Every life action can create at least one meaningful memory or tag.
- Endings can reference life-action history.
- Recaps feel different for a grinder, a caregiver, and a landlord-focused player.

### Phase 4: Singapore Cultural Texture Pack

**Purpose:** Make the game feel Singaporean beyond policy math.

**Build:**

- Cultural calendar events such as CNY, Hari Raya, Deepavali, Vesak, NDP, school holidays, monsoon months, and election/cooling-measure chatter.
- Everyday life events such as kopi talk, neighbour complaints, renovation delays, wedding-banquet pressure, parents' allowance, NS bookout, and school-zone anxiety.
- District personality hooks for at least the highest-traffic districts first.

**Success criteria:**

- A player can describe the game as Singaporean even before seeing CPF math.
- Cultural events are flavor-plus-consequence, not random trivia.
- Sensitive identity mechanics stay respectful and policy-grounded.

### Phase 5: MOP Home Season

**Purpose:** Make the first 60 months feel like a campaign, not a wall.

**Build:**

- Home-season timeline over the existing MOP chapters.
- First repair, first room tenant, first neighbour conflict, first renovation, reserve milestone, school-zone decision, and MOP celebration memories.
- Auto-advance to the next meaningful beat when months are quiet.
- End-of-MOP "your home changed your life" recap.

**Success criteria:**

- Active-MOP play has a visible near-term goal in every chapter.
- Players can skip quiet months without missing key decisions.
- MOP feels realistic but not empty.

### Phase 6: Family Light

**Purpose:** Add emotional stakes without overwhelming players.

**Build:**

- Spouse or partner as a simple pressure/support card.
- Parents, kids, and eldercare as lightweight obligations.
- School proximity and childcare pressure.
- Family-budget and household-load consequences.
- Ending hooks for Sandwich Generation, Quiet Achiever, Kiasu King or Queen, and Heartland Hero.

**Success criteria:**

- Family changes property decisions without becoming a full Sims-style relationship simulator.
- The player understands why family pressure changed a monthly recommendation.
- Family details enrich endings and memories.

### Phase 7: Replay Layer

**Purpose:** Give the game longevity.

**Build:**

- Ending collection screen.
- Run-history archive with life cards.
- Challenge starts and route-specific replay prompts.
- Optional shareable life-summary image.

**Success criteria:**

- A player has a reason to start a second run immediately after finishing.
- Ending collection shows discovered and undiscovered endings without spoiling all criteria.
- Share cards are accurate, readable, and spoiler-safe.

### Phase 8: Multi-Generation v1

**Purpose:** Deliver the long-term killer feature once the base life loop works.

**Build:**

- Child handoff at retirement or death.
- Inheritance of home, cash, debt, CPF-derived estate simplification, and one legacy trait.
- Family tree view.
- Generational endings.

**Success criteria:**

- The second generation starts with meaningful advantages or burdens from the first.
- The handoff is understandable in less than two minutes.
- The inheritance model is simplified but not misleading.

### Phase 9: Platform And Longevity

**Purpose:** Support long-term play and community features once the core game loop is worth preserving.

**Build:**

- Optional Supabase account-based cloud saves.
- Cloud run history.
- Leaderboards for challenge modes.
- PWA/mobile polish.
- Content pipeline for new scenario packs.

**Success criteria:**

- Local play still works without an account.
- Cloud features are additive, not required for the core game.
- New content can ship without destabilizing finance rules.

## Documentation Policy

As each phase ships:

1. Update `README.md` only with shipped behavior and a short pointer to this roadmap.
2. Add detailed release notes to `CHANGELOG.md`.
3. Keep implementation plans in `docs/superpowers/plans`.
4. Keep product direction and phase status in this roadmap.
5. Do not describe planned mechanics as live gameplay until the code exists and tests pass.

## Immediate Next Build

The next recommended build is **Phase 2: Causal Story Events v1**.

It has the best effort-to-impact ratio after the Lifetime Shell and Life Board work because it makes the next layer of fun come from consequences, not more panels:

- Landlord behavior should affect tenant-crisis odds.
- High leverage and weak reserves should increase financial-stress event risk.
- Burnout, district choice, ownership route, tenant satisfaction, renovation state, and reserve discipline should explain why specific life events appear.
- Scenario results should create stronger memories and ending signals.
- Monthly recaps should say why this beat happened and what it says about the player.
- The first scenario pack should add Singapore cultural texture without requiring a full family or multi-generation system yet.

This phase should be implemented before large new domains such as full childhood, true multi-generation, backend leaderboards, or a broad investment sandbox.
